## Вердикти
- "ERROR" — на сайті помилка (дата, ім'я, вік, зв'язок, хибна цитата), доведено сканом/документом.
- "HYP" — зв'язок чи ототожнення тримається на припущенні, а на картці нема hyp=true або в тексті нема «Є припущення … на підставі …».
- "OK" — знахідка хибна або вже пояснена на сайті (процитуй, де).
- "SCAN" — без кращого скану не вирішити (опиши, що саме подивитись).

## Виправлення — лише в такому форматі (manifest seed/import/manifest.json):
{"key":"au19j-<коротко>","kind":"personpatch","person":"<id>","set":{...},"replace":[["<точний шматок ЖИВОГО опису>","<новий>"]]}
{"key":"au19j-<коротко>","kind":"docpatch","id":"<doc>","data":{"line":"...","date":"..."}}   // data замінює ці поля повністю
{"key":"au19j-<коротко>","kind":"unionpatch", ... }  — не пропонуй, лише опиши в "note".
Шматок "replace" копіюй з live_0005b.json дослівно. Не вигадуй фактів: нове — тільки те, що є в документі/скані. Мова — українська.
Не пропонуй змін для сучасних живих людей (нар. після 1925), якщо нема документа — просто вердикт OK/SCAN з поясненням.

## Запис (пам'ять)
Після кожного випадку дописуй рядок JSON у свій файл adj_out/<ім'я>.jsonl:
{"case":"<ключ групи>","verdict":"...","why":"коротко, з посиланням на документ/скан","fix":[ ...патчі або [] ],"agent":"<ім'я>"}
Якщо файл уже є — пропусти розглянуті випадки.

## Для суддів сліпого читання (K)
Кожен випадок — документ, де сліпе прочитання скану розійшлося з рядком на сайті. Відкрий вирізку .../scratchpad/blind/<doc>.jpg і подивись САМ, хто правий: сайт чи сліпий читач. Сліпий читач не знав контексту й часто помиляється на нечітких місцях — це нормально; помилкою сайту вважай лише те, що на скані видно чітко інакше, ніж на сайті. Якщо сайт неправий — дай docpatch (новий повний "line", за потреби "date"/"title") і personpatch для картки (дата, replace в описі). Шматок для replace бери з live_0005b.json дослівно.
