# Рід Шутих — нотатки для розробки

- Мова інтерфейсу і відповідей — українська. Власник — Максим, не розробник: пояснювати просто, покроково.
- **Безпека понад усе (вимога власника):** браузер ніколи не звертається до Supabase напряму, жодних ключів на сторінці. Усе — через `api/*.js` з перевіркою сесії (`handler()` у `_lib.js`). Нові таблиці — тільки з `enable/force row level security` і `revoke all from anon, authenticated`. Файли — лише через `/api/file`.
- Кожна зміна даних → `revision()` (що було → що стало). Кожна дія перегляду → `track()` / `/api/track`.
- Ролі: `owner` > `editor` > `viewer`. Спогади можуть додавати всі, картки — редактор і вище, видаляти картки — лише власник. Фото будь-хто може додати будь-кому: поза своєю гілкою — чекає підтвердження власника (`settings.photo_pending`, Власнику → Доступи → «Нові фото від родичів», або кнопки на картці; поки не підтверджено — бачать лише власник і автор).
- Інтерфейс: ванільний JS (`public/app.js`), стан `S`, `render()` перебудовує `#app`. Без збірки, без бібліотек. CSP: скрипти лише `'self'`, без inline-скриптів і inline-обробників.
- Стиль: світлий, мінімальний, «архівний» (білий аркуш, чорнило, тонкі лінійки, Old Standard TT для імен). Один світлий вигляд.
- Статистика для власника — максимально розгорнута: періоди (готові й свій), порівняння з попереднім періодом, сортування колонок, журнал по кожному родичу.
- Перевіряти на 1440 px і 390 px. Локально: `npm run dev` (мок-база).
- Дані досліджень (люди, документи) — у `seed/seed.json`; після запуску сайту зміни вносяться через інтерфейс, не через seed.
- Перед кожним комітом змін інтерфейсу: `node tools/stamp.js` (версія в `public/version.json`, `BUILD` в app.js, `?v=` в index.html) — відкриті сторінки покажуть «Вийшло оновлення сайту → Оновити».
- Реєстрація родичів — посилання `/?join=<код>` (Власнику → Доступи); заявки `join_requests` (міграція 003) приймає власник, прив'язуючи до картки. Запитання родичів — `questions` (002).
- Рамки «наш запис» на сканах: `documents.data.marks = [{p,x,y,w,h}]` (частки зображення); показує `viewer()` (кнопка «Показати наш запис»), редактор обводить сам (⋯ → «Обвести наш запис рамкою», op `doc.marks`). Нові архівні документи — одразу з рамкою й описом «яка сторінка, який запис за рахунком, №». Імпорт уточнень існуючих документів — kind `docpatch`.
- Дерево відкривається з картки людини, яка увійшла (`startId()`).
- «Історія роду» (Родини → перша вкладка) і «Історія сіл» (Карти й історія) — тексти в `settings` під ключами `text:history` (`{md, updated}`, Markdown з посиланнями `[[p:id|Ім'я]]`, `[[d:id|текст]]`) і `text:villages` (`{intro, sections[{title, items[{y,t,src[{name,url}]}]}], sources, ask}`); віддає `GET /api/data?text=<k>`, імпорт — kind `text`. Кожен факт — з джерелом; припущення — «Є припущення».
- Нові матеріали з `seed/import/manifest.json` сайт вносить сам: кожне відкриття сайту будь-ким викликає `POST /api/setup?a=sync` (якщо manifest не змінився — `settings.import_ver`, миттєво); помилка одного пункту не зупиняє решту. Тексти історії, поки не імпортовані, `GET /api/data?text=` віддає прямо з manifest. Кнопок для власника не робити — усе автоматично.
- «Історія роду» показується як стара книга (`bookShell/bookMount/bookPaginate/bookFlip` в app.js): текст розкладається по сторінках вимірюванням, гортання — CSS 3D. Звуки й музика — `public/audio/*.mp3` (створені локально: музика — власна композиція, синтез через fluidsynth + TimGM6mb; гортання, скрип і стук — синтез numpy), вмикаються лише після кліку «Відкрити книгу», кнопка 🔊/🔇 пам'ятає вибір (`localStorage rs_snd`). «Текстом» — звичайний вигляд.
- Телефон (≤820 px, правила як у KRental CRM): шапка 52 px лише з назвою; нижнє меню `.bnav` (`mNav`: Дерево, Історія, Люди, Документи + «Ще») і шторка «Ще» `mSheet()` (карти, запитання, власнику, вийти). Кнопки ≥44 px, поля 16 px, фільтри — один рядок з прокруткою вбік, довгі таблиці — списком рядків (`.t.plist`). Книга: панель гортання закріплена над меню, шрифт і «Читати текстом» — у змісті (`.bk-tset`).
- Мова текстів (вимога власника): «що вона **і є**», а не «й є»; сполучник «й» не ставити перед «є».
- Вигляд (13.10): теплий папір, винний акцент `--wine`, картки з тінню, аватари з ініціалами (`avatar()`), клік по людині — бічна панель `ppHtml/ppOpen` (другий клік закриває). Шапки сторінок компактні (`.lede`: h1 + один рядок). **Рядок вкладок не рухається**: заголовок сторінки однаковий для всіх вкладок, опис вкладки — під вкладками (`.tabnote`); у дереві одна панель `treeBar()` для всіх режимів.
- **«Історія роду» оновлюється разом з кожною знахідкою (правило власника, 13.10):** додали людину, документ, дату чи уточнення — у тому ж коміті оновити `text-history` у manifest (відповідний розділ, посилання `[[p:…]]`/`[[d:…]]`, «Що ще шукаємо»). Те, що відомо зі слів родичів, — «за словами …».
- Діти, що померли малими (до 15 років), — окремі картки з датами; на дереві позначка † (`childAge()`/`kdBadge()`), у описі — вік на момент смерті.
- **Кожен знайдений факт — зі скріншотом і посиланням (правило власника, 13.10):** якщо щось знайдено в джерелі (метрика, база «Память народа», стаття, сайт) — на сайт додається документ зі сканом/скріншотом (kind `doc`, рамка на потрібному рядку, опис «яка сторінка, який рядок») і посилання на джерело (`url`), а людина прив'язується через `people`. Лише посилання (`src`) без скріншота — недостатньо. Старі факти, де є лише посилання, поступово доповнювати скріншотами.
- **Лише підтверджене (правило власника, 13.10):** у «Історії роду», «Історії сіл», картках — тільки те, що є в джерелі; власні висновки й здогадки — або прибрати, або позначити «Є припущення» з поясненням, на чому воно базується.
- **Зв'язок живих родичів (13.10):** `person.data.links = [{t,u}]` (t: tel, vb, tg, wa, ig, fb, tt, yt, li, web). Сервер нормалізує й перевіряє (`cleanLinks/normLink` у `_lib.js`: лише https на відомі сайти, телефони — цифри). Змінює редактор будь-кому або родич — свою картку (op `person.links`). Показ: блок «Зв'язок» на картці (`socBlock`) і значки в бічній панелі (`socChips`). `person.save` не губить `src`/`links`, яких немає у формі.
- **Автор сайту (бажання власника):** підпис «Сайт створив і веде Максим Шутий» — внизу сторінок (`creditHtml`, крім дерева), на вході (`.lg-cr`), у шторці «Ще» (`.msh-cr`), на обкладинці книги (`.bk-by`). Не прибирати.
- **Головна та розділи для родини (13.10):** `#/home` (стартова: цифри, група Telegram, «Цей день», «Ким ми доводимось», голоси, «Допоможіть знайти», «Хто на фото?», запрошення), `#/kin` (`kinship()`/`kinWord()`), `#/stats` (`vStats`, таблиці `.sortable`), `#/help`, `#/geo` (карта роду: місця з `bp/dp` і документів, координати — `PLACE0` + `settings.places`, ставить редактор кліком), `#/dna`. Спільні налаштування — `settings` ключі `tg_group`, `photo_ask`, `wanted`, `dna_matches`, `places` (віддаються в `cfg` з `/api/data`; ops `cfg.tg`, `photo.ask`, `want.save/del`, `dna.save/del`, `place.set`). Підказки й відповіді — `stories` з target `photo:<id>` / `want:<id>` (пише будь-хто).
- **Голосові спогади:** таблиця `photos` з `mime audio/*` (шлях `voice/…`), запис у браузері `MediaRecorder` 32 кбіт/с до 15 хв; ті самі правила підтвердження, що й для фото. Відтворення — `fetch` → blob (CSP `media-src 'self' blob:`, `microphone=(self)`).
- **Плакат:** `treePng(PO)` → `posterCompose()` (A2/A1/A0, 300 dpi у межах браузера).
- **«Припущення» (`#/hyp`, у шапці):** усе непідтверджене — курований список `text:hyps` у manifest (`{intro, items[{id, kind:'hyp'|'kin', title, text, basis, people, docs, src}]}`) + автоматично: картки `hyp`, речення з «Є припущення» в картках/документах/«Історії роду», шлюби «не підтверджено». Відповіді родичів — `stories` target `hyp:<id>` з позначкою `[yes]/[no]/[add]`. Нову можливу рідню й нові припущення — додавати в `text:hyps`.
- Manifest: змінений пункт (інший хеш) виконується ЗНОВУ — не правити текст `append` у вже імпортованих пунктах (задвоїть опис); виправлення — окремим personpatch `set`/`replace`.
- **«Хто на фото?» — фото без картки:** кнопка «＋ Фото: хто на ньому?» (Головна, «Допоможіть знайти») → `/api/upload?ask=1&caption=` (person_id `_ask`; від не-редактора — чекає підтвердження власника) → `photo.ask` (родич може позначити лише своє `_ask`-фото). Підказки — stories `photo:<id>`.
